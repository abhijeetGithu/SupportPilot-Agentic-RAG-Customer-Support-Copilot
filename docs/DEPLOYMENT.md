# Deploying SupportPilot for free

Everything below runs on free tiers with no credit card:

| Part | Service | Free tier used |
|---|---|---|
| Frontend (Next.js) | **Vercel** Hobby | always on |
| Backend (FastAPI + models) | **Render** free web service | 512 MB RAM, sleeps after 15 min idle (wakes in ~1 min) |
| Vector search | **Qdrant Cloud** free cluster | 1 GB RAM / 4 GB disk (we use ~1,565 points) |
| Database (tickets, chat memory) | **Neon** Postgres free | 0.5–1 GB, scales to zero |
| LLMs | **Groq** free tier | your existing key |

```
browser ──► Vercel (Next.js pages)
   │
   └──(API + streaming, direct)──► Render (FastAPI, int8 ONNX models) ──► Groq (LLMs)
                                        ├──► Qdrant Cloud (docs + KB search)
                                        └──► Neon Postgres (tickets, chat memory)
```

The browser calls the backend directly (not through a Vercel rewrite): proxies can buffer the token
stream and add timeouts.

## Why the backend fits in 512 MB
Measured on the production dependency set (`pip install .`, no PyTorch), with a realistic workload
(startup, a chat answer, a ticket, a screenshot upload, staff pages): **peak 401 MB**, steady ~380 MB.
- Ticket classifiers: fine-tuned DistilBERT exported to ONNX and quantized to int8 (268 → 67 MB each),
  run on onnxruntime, loaded one at a time per ticket and released (`CLASSIFIER_KEEP_LOADED=false`).
- onnxruntime memory arenas off (single request at a time), llama-index loaded only when publishing.
- scipy / scikit-learn replaced by small tested NumPy code; optional providers moved to extras.
Before these changes the same workload peaked at 529 MB.

## 1. Qdrant Cloud (search index)
1. Sign up at https://cloud.qdrant.io, create a **Free** cluster (any region near you).
2. Copy the **cluster URL** (`https://....cloud.qdrant.io:6333`) and create an **API key**.
3. With your local Qdrant running (`docker compose up -d qdrant`), copy the index (vectors included, no
   re-embedding; ~1 minute):
   ```powershell
   .venv\Scripts\python scripts\migrate_qdrant.py --dst https://YOUR-CLUSTER.cloud.qdrant.io:6333 --dst-key YOUR_API_KEY
   ```
   It should end with `done: 1563 points`. (KB articles are skipped: publish them again on the live site.)

## 2. Neon (database)
1. Sign up at https://neon.com, create a project (Postgres 16+).
2. Copy the **connection string** (`postgresql://USER:PASSWORD@HOST/DB?sslmode=require`). The app accepts
   it as is. Tables are created automatically on the first start.

## 3. Publish the classifier models (GitHub release)
The int8 models are too big for git, so the Docker build downloads them from a release.
1. Create the zip (once): `.venv\Scripts\python scripts\package_models.py` → `dist/classifiers-onnx-int8.zip`.
2. On GitHub: your repo → **Releases** → **Draft a new release** → tag **`models-v1`** → title
   "Classifier models" → attach `dist/classifiers-onnx-int8.zip` → **Publish**.

## 4. Render (backend)
1. Sign up at https://render.com with GitHub.
2. **New → Blueprint** → choose this repository (it reads `render.yaml`).
3. Fill in the secrets it asks for:
   | Variable | Value |
   |---|---|
   | `GROQ_API_KEY` | your Groq key |
   | `DATABASE_URL` | the Neon connection string |
   | `QDRANT_URL`, `QDRANT_API_KEY` | from step 1 |
   | `STAFF_PASSWORD` | your admin password (12+ characters; keep it private) |
   | `DEMO_PASSWORD` | the read-only password you'll share (e.g. on your resume) |
   | `CORS_ORIGINS` | `["https://placeholder.vercel.app"]` for now (step 6 fixes it) |
   | `PUBLIC_APP_URL` | `https://placeholder.vercel.app` for now |
   `JWT_SECRET` is generated by Render. `ENVIRONMENT=production` makes the app refuse to start with
   default secrets.
4. Deploy. The first build takes ~5–10 minutes. Check `https://YOUR-SERVICE.onrender.com/health`
   → `{"status":"ok"}`.
   `CLASSIFIER_KEEP_LOADED=false` and `DAILY_CHAT_LIMIT=300` are preset in `render.yaml`.

## 5. Vercel (frontend)
1. Sign up at https://vercel.com with GitHub → **Add New → Project** → this repository.
2. **Root Directory: `frontend`** (Framework: Next.js is detected).
3. Environment variables:
   | Variable | Value |
   |---|---|
   | `NEXT_PUBLIC_API_BASE` | `https://YOUR-SERVICE.onrender.com/api` |
   | `NEXT_PUBLIC_DEMO_LOGIN` | `demo:YOUR_DEMO_PASSWORD` (shown on the login page) |
4. Deploy and note the URL, e.g. `https://supportpilot-xyz.vercel.app`.

## 6. Connect them
In Render → your service → Environment:
- `CORS_ORIGINS` = `["https://supportpilot-xyz.vercel.app"]`
- `PUBLIC_APP_URL` = `https://supportpilot-xyz.vercel.app`

Save (Render redeploys).

## 7. Smoke test
- [ ] Open the Vercel URL. If the backend was asleep, a "Waking up the AI backend" bar shows for ~1 min.
- [ ] Chat: "How do I add Jira as a content source?" → streamed answer with sources and "Checked against the docs".
- [ ] Contact form ticket → visible in the dashboard (admin login).
- [ ] Demo login (`demo` / your demo password) → dashboard visible, changes refused ("read-only").
- [ ] Resolve a ticket with a staff reply → KB draft → publish → ask the chat again.

## Free-tier behaviour to know
- **Render** sleeps after 15 minutes without traffic; the first request wakes it (~1 min). The frontend
  shows a banner meanwhile. Files uploaded to tickets live on Render's disk and **are lost when it sleeps
  or redeploys** (fine for a demo; use object storage for real use).
- **Groq** free tier: 200K tokens/day per model. The API caps assistant turns at `DAILY_CHAT_LIMIT`
  (300/day) and rate-limits per IP, so one visitor can't use up the day.
- **Qdrant Cloud** free clusters may be paused after a week without use: resume it in the Qdrant console.
- **Neon** suspends compute when idle; the first query after that takes ~1 s.

## Updating
Push to `main`: GitHub Actions runs tests, lint and the frontend build; Render and Vercel redeploy
automatically. New classifier models: bump the release tag and `CLASSIFIER_URL` in the Dockerfile.
